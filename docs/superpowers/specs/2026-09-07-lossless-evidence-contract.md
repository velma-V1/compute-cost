# Lossless Benchmark Evidence Contract

**Status:** Required extension to `base-v1`
**Date:** 2026-09-07

## Requirement

Every observable datum produced, received, sampled, derived, scored, logged, or generated by a benchmark run must be retained. The benchmark must never discard raw evidence merely because a normalized field or summary has already been produced.

The evidence store is the source of truth. `summary.json`, `report.md`, comparison tables, and scores are derived views and must be reproducible from retained evidence wherever the underlying runtime exposes the necessary data.

## Boundary of "Every Piece of Data"

The harness must capture **all data it can actually observe** through the runtime API, subprocesses it launches, benchmark code, operating-system sensors, NVIDIA tooling, scorer execution, and its own event stream.

It cannot claim to capture internal model/runtime state that is not exposed by those interfaces. Unobservable fields are explicitly marked `unavailable` with the reason and collection method attempted.

Secrets are the only intentional exclusion: the harness must not dump arbitrary environment variables, credentials, authorization headers, cookies, tokens, or unrelated user files.

## Lossless Capture Rule

For each observation, preserve both:

1. **Original evidence** — exact raw payload/text/bytes or exact command output as observed, with timestamps and provenance.
2. **Normalized evidence** — parsed fields used by scoring, analysis, reporting, and comparison.

Normalization must never overwrite the original.

## Required Capture Classes

### Run provenance

Capture:

- run ID and parent/replay relationships
- benchmark/suite version
- repository git commit when available
- exact benchmark definition snapshot used by the run
- exact resolved configuration after defaults and CLI overrides
- runtime adapter version
- Python/package versions relevant to the benchmark
- wall-clock and monotonic timestamps
- model identifier plus all runtime-exposed model metadata
- hardware and runtime preflight snapshots

### Runtime requests

For every model interaction retain:

- request ID
- stage and case ID
- exact system/user/assistant/tool-shaped messages supplied to the runtime
- exact prompt when a flat prompt API is used
- generation/sampling parameters
- context/window controls
- format/schema request
- timeout and stop sequences
- adapter-transformed request payload
- raw serialized request body when observable and safe
- send/start timestamps

### Runtime responses

Retain all runtime-exposed response data before parsing:

- raw response body or streaming chunks/events
- exact generated text
- exposed thinking/reasoning fields when the runtime supplies them
- tool-call fields
- finish/stop reason
- token counts
- prompt/eval durations
- model-load duration
- runtime timestamps
- runtime warnings/errors
- HTTP/status metadata that is safe to retain
- any additional response keys not recognized by the current parser

Unknown fields must be preserved, not silently dropped.

### Streaming timeline

When streaming is enabled, retain each observable chunk/event with:

- sequence number
- receive timestamp (wall and monotonic where available)
- raw event payload
- cumulative output length

This enables exact TTFT/inter-token latency analysis later rather than only storing aggregate speed.

### Telemetry

Retain every sample, not just peaks/averages.

Host/process telemetry should include fields available from the chosen APIs, including:

- CPU utilization and frequency
- logical/physical core information where available
- host RAM total/available/used
- benchmark/runtime process RSS/VMS and CPU usage when observable
- disk free/used relevant to model/result paths
- process IDs for benchmark-owned or identified runtime processes

NVIDIA telemetry should retain every field requested and returned by `nvidia-smi`, including where available:

- GPU identity/index/UUID
- driver/version metadata
- utilization
- memory total/used/free
- temperature
- power draw and enforced/default power limit
- graphics/SM/memory clocks
- performance state
- fan speed

Sensor command stdout/stderr, return code, and parse errors are retained so missing/invalid samples can be audited.

### Timing

Record stage, request, scorer, subprocess, telemetry, and total-run durations from monotonic clocks. Preserve wall timestamps separately for correlation.

For model requests, retain enough events to calculate:

- queue/start time where observable
- request-send time
- first response/chunk time
- final response time
- TTFT
- inter-token/chunk timing when observable
- total latency
- runtime-reported prompt/eval/load durations

### Capability/scoring evidence

For every case retain:

- exact benchmark case definition snapshot
- exact instantiated input
- raw model output
- parsed output
- scorer type/version
- expected answer/schema/tests
- every scorer check and subscore
- parser/scorer stdout/stderr when subprocesses are used
- final score and status
- scorer exception/traceback when applicable

### Coding-task evidence

For executable coding cases retain all benchmark-generated/observed artifacts needed for forensic review:

- generated source text
- extracted source actually executed
- test source/version
- temporary file manifest and SHA-256 hashes
- invocation command
- cwd relative to the isolated case workspace
- exit code
- stdout
- stderr
- timeout/termination reason
- execution duration

Do not retain unrelated host files or secrets.

### Context-sweep evidence

For every context level retain:

- requested target length
- generation recipe/seed for synthetic context
- exact generated context or a content-addressed retained artifact
- planted facts and locations
- runtime-observed token counts
- full request/response evidence
- full telemetry slice
- correctness/scorer evidence
- stop-boundary evaluation and reason

### Sustained-load evidence

Retain every iteration, not only aggregate drift:

- iteration sequence
- exact case/request
- raw output
- timing/token data
- telemetry interval
- errors/retries
- resource and throughput measurements

### Failure evidence

A failure snapshot must capture the exact observable state at the failure point:

- stage/case/request ID
- typed failure
- exception type/message/traceback from benchmark code
- runtime raw error payload
- subprocess command/stdout/stderr/return code
- last telemetry samples before/at failure
- resolved config
- request payload
- partial/streamed response already received
- scorer/parser state already produced
- replay recipe

Failures must remain independently replayable without rerunning unrelated cases.

### Derived-analysis provenance

Every derived metric must retain:

- metric name/version
- formula or algorithm identifier
- exact source artifact/field references
- units
- result
- classification as `derived` or `estimated`
- assumptions for estimated metrics

## Evidence Directory

Each `results/<run-id>/` contains at minimum:

```text
manifest.json
resolved-config.json
benchmark-snapshot.json
hardware.json
runtime.json
events.jsonl
telemetry.jsonl
cases.jsonl
summary.json
report.md
raw/
  runtime/
    requests/
    responses/
    streams/
    errors/
  telemetry/
    host/
    nvidia/
  subprocess/
  scoring/
  cases/
replay/
```

Large raw evidence may be stored content-addressed under `raw/objects/sha256/<digest>` with lightweight references from JSONL records. The exact original bytes/text must remain recoverable.

## Manifest and Integrity

The manifest inventories every retained artifact with:

- relative path or content-addressed object ID
- byte size
- SHA-256 digest
- media/record type
- producer/stage/case where applicable

Manifest finalization occurs only after all run artifacts are flushed. Integrity verification must detect missing, added-untracked where required, or modified artifacts.

## No Silent Loss

Adapters and parsers must preserve unknown fields from runtime and telemetry responses in a `raw` payload or raw artifact. Schema evolution may add normalized fields later without requiring the original benchmark to be rerun.

If capture of an expected channel fails, emit a `CAPTURE_GAP` event containing:

- channel
- attempted collector
- error
- affected time/case range
- whether primary benchmark execution continued

## Storage Policy

Raw result directories remain local and gitignored by default. The harness reports total evidence bytes written per run so evidence-storage cost itself becomes part of onboarding cost.

Optional compression may be added later only if decompression is lossless and hashes are defined unambiguously over original and/or stored bytes.

## Acceptance Additions

`base-v1` is not complete unless:

1. Raw requests and raw responses are retained before parsing.
2. Streaming chunks are retained when the runtime exposes streaming.
3. Every telemetry sample and raw collector output/error is retained.
4. Unknown runtime response fields survive capture.
5. Exact scoring inputs, checks, outputs, and failures are retained.
6. Coding subprocess stdout/stderr/exit/timing and executed artifacts are retained.
7. Failures produce exact-point replay snapshots.
8. Benchmark and resolved-config snapshots are retained per run.
9. Every retained artifact is content-hashed/inventoried.
10. Every expected-but-unobservable or failed capture channel is explicitly represented as unavailable or `CAPTURE_GAP` rather than omitted.
11. Evidence byte count is reported.
12. Summary and report generation do not delete or replace original evidence.
